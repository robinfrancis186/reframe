# Reframe

A local component workbench: capture an interface, pick reusable elements, adapt them to your project theme, save them, and insert them into connected web or native projects.

See the [product and usability audit](docs/PRODUCT_AUDIT_2026-10-22.md) for current capability ratings, market comparisons, implemented workflow improvements and remaining release gates.

## Run

```sh
npm install
npm run dev
```

Open http://localhost:5173. The server binds only to 127.0.0.1. The project includes a local Node 24.11.1 development runtime to meet REA's engine requirement; npm scripts select it automatically. No global Node installation is changed. Native decompilers and device agents are not installed.

```sh
npm test
npm run check
npm run build
npm start
```

Stop the dev server before starting production on the same port. Production serves the built frontend and API together. Run `npm run verify` for TypeScript, the Node suite and all three web builds. See [release configuration and hosting gates](docs/RELEASE.md). This build is intended for a single user on their own machine; it is not a publicly hosted multiuser service.

## Built-in reference browser

Open **Browser** or **Browse & pick** in Studio. The backend starts an isolated headless Chromium session on demand and renders it inside Reframe as interactive snapshots. It first uses installed Google Chrome; if Chrome is unavailable, install Chromium with `npx playwright install chromium`. The browser integration tests require either runtime. This is a real rendered browser, not an external-site iframe.

- Open up to four tabs. Navigate with the address bar, links, back/forward, reload and scroll controls. Click, hover and drag in the page. Wheel scrolling targets the area under the pointer, including nested scroll containers. Click a field, then use **Type into page** or paste into the focused page surface. Tab, Shift+Tab, arrows, selection, Enter and Escape are forwarded; Escape returns focus to Reframe's typing field. Failed typing preserves your text. Live snapshots can be paused.
- Switch between a 1280×800 desktop viewport and a 390×844 narrow viewport. The narrow setting changes layout width; it is not iOS/Safari emulation.
- Turn on **Pick element**, click a component and optionally **Select parent container**. Choose **Adapt in Studio** or **Save directly to clipboard**. Direct saves update an existing matching source/HTML item instead of duplicating it.
- Picks retain sanitized HTML, applicable source CSS, inline SVG, source URL, capture time and a cropped reference image. Clicking text or an icon selects its enclosing interactive control. Browser-picked packages preserve original styling, bundle public PDF downloads and include an independently authored local website runtime. **Original reference** in Studio shows that image next to the Preview/Code controls; it survives saving, reload and JSON backups. It is an appearance reference, not a claim to recover scripts or business logic.
- **Load whole page** scans from the top to load content triggered by scrolling, waits for styles/fonts/resources, then restores your position. **Capture page sections**, **Scrape page** and **Full-page screenshot** also perform this scan. It is bounded to 40 scroll steps / roughly 20,000 pixels; limits are reported.
- **Scrape page** reads rendered text, headings, links, image metadata and labelled controls, with a downloadable JSON report. Typed field values and cookies are excluded. Text is limited to 100,000 characters, with bounded metadata lists and explicit truncation indicators. Canvas, closed shadow roots and cross-origin frame contents are not extracted.
- **Use screenshot** takes a fresh viewport screenshot and transfers it into reconstruction without uploading automatically. **Full-page screenshot** downloads a JPEG; pages taller than 20,000 pixels export the first 20,000 pixels and show a notice. Picks retain their own cropped reference image.
- **Website access** defaults to GET/HEAD/OPTIONS. Explicitly enable submissions for the current origin to use its forms and APIs; then retry the intended action. POST/PUT/PATCH/DELETE bodies are capped at 1 MB. Permission resets on leaving the origin or closing the tab. Cookies remain isolated in that temporary tab and are never exported.
- Website alerts, confirmation dialogs and prompts appear inside the browser with explicit response controls. New-window links retain their requested destination and can be opened in another isolated tab; they do not silently replace the current page.
- Bookmark pages to a local reference collection. Up to 30 saved references persist in this browser. Tabs and isolated sessions expire after 20 minutes without activity or when the server restarts; bookmarks and clipboard items persist.

Requests preserve framework headers (including Next.js client navigation), use DNS validation and pinned public addresses, and queue resource bursts behind 16 concurrent fetches instead of dropping assets. Limits are 8 MB per resource and 1,200 requests / 64 MB per document navigation. **Page & resource report** shows failed resources, script errors, image completion and pending requests. Browser-native network traffic, private networks, page-triggered file downloads, WebSockets, streaming responses and camera/microphone access remain unavailable. Other origins' writes remain blocked even when the current origin is enabled. Some sites block automated browsers or require unsupported flows. Browser capture, scraping and screenshots do not require an OpenAI key.

The clipboard, including original images and embedded fonts, is stored in this browser's IndexedDB (an existing localStorage clipboard migrates automatically on first load). Picked components embed only the font faces they render. Browser storage is still per-browser and can be cleared with site data, so export backups regularly; save errors are reported and preserve the previous library. The screenshots are not included in exported component source.

## Reusable working features

Open any captured component in Studio and choose **Build working feature**. The local inspector identifies data fields and actions, suggests intent from visible text, and lists missing behavior. Review required fields and choose each action's behavior. Unresolved actions block generation.

Supported authored behaviors: create/update/delete/search records, persist an on/off state, increment a counter, navigate, show authored details, reset fields, create accounts, sign in/out, and call a configured HTTPS API. These build our own logic from a declared contract; captured private APIs or business rules are not recovered. Password fields can only feed authentication actions, never records or external API payloads. Radio/select choice models, payments and OAuth-specific flows still need dedicated adapters.

**Generate frontend + backend** creates an eleven-file package, or twelve files with authentication: React UI/account panel, SwiftUI UI and Foundation client, Android platform view with a Material 3 Compose wrapper, schema, Node API/storage and identity/integration services, web/native runners and setup documentation. Review these files, then **Save full feature to clipboard**. Clipboard reload, JSON backup/import and **Export full feature** retain the complete package. Imports and installations recompile declared metadata through the trusted generator; executable text from imported packages is not installed blindly. Editing captured HTML invalidates its built feature.

In Projects, connect a React + Vite app or choose **Use clean app**. Select a screen/container, review all file changes and apply. Reframe inserts a component import, installs its API and runtime under `reframe/`, adds `reframe:dev` / `reframe:start` scripts, and adds the data directory to `.gitignore`. Existing scripts are preserved. Rebuilding the same feature ID and choosing its existing import name updates its files without inserting another component. Restart the destination after updates so its API contract reloads. Run **npm run reframe:dev** inside that app to serve frontend and backend together at port 5175; override `PORT` when needed. For production, run its build command and **npm run reframe:start**. Development WebSockets share the HTTP server. No extra package dependencies are added.

The independent Haven example is `examples/integrated-app`. Packages operate without Fieldnotes' demo handler. Automatic full-stack installation supports React + Vite, SwiftUI and Android Compose. **Use iOS app** connects `examples/native-ios`; **Use Android app** connects `examples/native-android`. Native installation adds the UI/client, backend, launch script and data ignore rule. Android also receives INTERNET permission and a debug-only localhost network policy; custom existing policies require explicit review. Native backend: `npm run reframe:backend` on port 5176. The iOS starter has an Xcode 16+ project with synchronized source folders and a SwiftPM macOS preview; Android has a pinned, checksum-verified Gradle wrapper and Compose build project. Other runtimes, including full-stack React Native, still require an adapter.

APIs are namespaced per feature (`/api/reframe/rf_…`). They enforce declared actions and field types, reject stale versions and conflicting request IDs, serialize writes and atomically persist data in `.reframe/data/`. A feature supports up to 200 records, 10,000 writes and a 16 MB local store. Optional accounts isolate records, counters, toggles and request history by user. Clipboard packages contain source/schema, never destination accounts, keys or records. Transactional database hosting is not included.

## Authentication and your own API keys

In **Build working feature**, enable **Require sign-in** for private data. Email/password login captures can use **Sign in**, **Create an account**, or **Sign out** actions. A generated **Account & API keys** panel provides account setup for other captured components. Existing public records remain preserved separately when authentication is enabled; they are not assigned to an arbitrary user.

Choose **Call an external API** for an action, set its public HTTPS endpoint and GET/POST method, map captured fields to request parameter names, and choose no key, Bearer token, or X-API-Key. GET sends query parameters; POST sends JSON. After installation, users sign in and enter their own key in **Account & API keys**, which displays the exact destination. Keys can be replaced or removed. Keys are encrypted with AES-256-GCM, bound to the user/endpoint/method/header type, and never included in clipboard packages or returned by credential-status endpoints. Echoed copies of the supplied key are redacted from returned JSON. A different endpoint needs its own key setup.

Accounts use salted scrypt hashes, bounded login attempts and revocable 24-hour sessions. Web sessions use HttpOnly, SameSite=Strict cookies scoped to the destination; native clients use in-memory bearer tokens. Passwords are not saved as component data. Identity/vault files are owner-only under `.reframe/security/`; keep this folder private and back up `vault.key` securely with its encrypted credentials. Losing that key makes saved API keys unreadable. Account/key setup is per destination app, not cloud synchronization.

External requests validate and pin public DNS addresses, block local/reserved networks, reject redirects and URL credentials, time out after 10 seconds and accept JSON responses under 100 KB. Only declared fields are sent. Successful request IDs deduplicate retries. A POST intent is saved before sending; if its outcome is uncertain, subsequent POSTs for that action are blocked until an operator reconciles the provider outcome and resolves the pending request in the local store. An Idempotency-Key header is supplied, but provider support is not assumed.

The local account service does not include email verification, password recovery, MFA, OAuth/SSO or team roles. It remains loopback-only and uses process-local queues. Public hosting needs TLS/Secure cookies, managed identity lifecycle/secrets and database transactions. The legacy catalog demo on port 5174 remains a separate single-workspace example; the authenticated integration demo is Haven on port 5175.

Multi-file review checks every destination for later edits and symlinks before writing. A durable change journal supports recovery after interrupted installation. Undo restores generated source/configuration, refuses to overwrite later edits, and preserves user data. Browser-loaded modules and cached API handlers may remain active until the destination process is restarted after Undo; restart before retesting a removed feature.

## Native capture and direct integration

1. Open **Native devices**. Android uses an authorized device or emulator through [ADB](https://developer.android.com/tools/adb). iOS uses a booted Xcode Simulator; [modern idb](https://fbidb.io/idb/ui/) adds accessibility hierarchy capture. The app detects unavailable tools and shows setup guidance. Physical iPhone screenshots can be imported; direct physical iPhone inspection is not supported.
2. Capture a screen and choose a hierarchy node, or import UIAutomator XML / idb JSON. Screenshot-only captures support a selectable crop. Reconstruction uses local macOS OCR when no OpenAI key is configured, or the configured remote model. Local OCR extracts text and suggests controls; it does not reproduce graphics or hidden behavior. Native hierarchy picking works without a model.
3. Save the picked element to the clipboard, then choose **Check project fit**. In **Projects**, connect an absolute local app folder or choose **Use starter app**.
4. Drag a clipboard item onto the destination panel, choose the screen and a recognized container, and give the generated component a unique `Reframe…` name. React/React Native uses JSX containers; SwiftUI uses view-builder containers; Compose uses ordinary Column/Row/Box containers.
5. For a working feature, review and apply all UI/client/backend files together; its declared actions call the included API. For a UI-only capture, connect actions to an existing local handler before source insertion. SwiftUI and Compose working-feature installations create separate reusable source files beside the destination screen.
6. **Undo integration** survives server restarts and refuses to overwrite subsequent edits. Apply also refuses stale previews. No Git commands or project scripts run during integration.

The included editable destination is `examples/connected-app`. Start it in a second terminal:

```sh
npm run demo
```

Open http://localhost:5174. The demo now runs its own Express API and Vite frontend together. Its captured Apple action group operates our original **Pocket Set** product: Learn more opens catalog details; Pre-order opens cover/quantity selection, a persistent cart, and a local reservation receipt. `handleReframeAction` keeps the original action1/action2 contract and connects it to this real flow. Connect it with **Use starter app**.

The catalog API owns prices, validates quantities and stock, rejects stale cart versions, and atomically saves cart, inventory and reservations in `examples/connected-app/.reframe/shop.json` (ignored, owner-only storage). Repeating a reservation request ID returns the same receipt without decrementing stock twice. Reloading or restarting preserves data. This is a single local workspace, not separate customer carts. No payment, fulfillment, authentication or public hosting is included. These are our own product rules, not recovered Apple business logic.

API: `GET /api/shop`, `PUT /api/shop/cart` with `{variantId, quantity, version}`, and `POST /api/shop/reservations` with `{version, requestId}`. Prices and totals cannot be supplied by the client. The standalone example requires Node 24.11+; run `npm install && npm run dev` inside it, or use the root `npm run demo` with already-installed dependencies. For its production build, run `npm run build` and `npm start` inside the example. The example source and backend must travel together; an HTML clipboard export alone does not include this business behavior.

Generated SwiftUI uses semantic fonts and accent color. Compose uses Material 3's enclosing theme. React inherits typography and CSS color tokens. React Native receives the selected colors through a theme prop; wire that prop to the app's theme provider for live theme changes. Stateful text/toggle inputs are generated. Working packages include API-backed actions. UI-only exports require application handlers; their unbound actions explicitly log IDs.

Automatic integration is intentionally limited to supported source containers. Next.js interactive insertions require an existing client component. Material 2 screens and Compose lazy-list DSLs are not automatic destinations. Media becomes an accessible description until you supply destination assets. Generated native source must be built with the destination app's SDK and dependencies.

## Test before installation and connect project data

Studio’s **Test behavior → Start working preview** compiles a canonical React/backend package into a disposable local process. It has separate records and test accounts; reload keeps them, **Reset test data** starts clean, and **Stop preview** removes them. Leaving the component stops the preview. Up to three sessions run at once and expire after 30 minutes. No OpenAI key or other server credentials are inherited by the runtime. External API calls, credential writes and generated navigation are blocked. This is a local trusted-code preview, not an OS sandbox for arbitrary uploaded code. A forced server/machine crash can leave temporary files under `.reframe/previews/`; do not use real credentials or sensitive test data.

**Test this preview with Playwright** opens Sentry’s real browser runner with the current preview selected. Specify actions and visible expectations; the report records only those assertions. Success in the preview does not prove behavior in a different destination or native device. Account/API requirements and destination testing remain explicit.

The **Searchable list** and **Table** React exports accept host data through `items` and `rows`. Search also accepts `onSelect(value)`. In Projects, **Use project data** offers compatible arrays declared in the chosen container’s lexical scope, including recognized `useState` initializers. Search selection can call an existing string handler. The installer validates the binding against current source and rejects invented expressions. Empty, imported or complex data sources are not inferred automatically; pass them through the exported typed props in code. Table rows need unique names and numeric progress. Native exports keep their existing sample data.

Haven includes an app-owned resource list, an Add resource form and a selection callback wired to the installed Searchable list. This example is page-session state, not persistent API storage. Existing feature records and accounts are separate and preserved.

Heavy tool screens load on demand. A failed view has a reload recovery screen without clearing clipboard storage.

## Capture media and check fit

- **Screenshot** accepts PNG, JPEG and WebP. Images are resized locally to a maximum dimension of 1280 pixels.
- **Video** accepts browser-playable files up to 100 MB. Scrub the clip and capture up to six frames showing the component and its states. Remove frames before submission as needed.
- **Camera** asks browser permission only when you choose **Start camera**. Capture individual frames or record up to 60 seconds, then review the clip. Audio is never recorded. Closing the dialog, changing capture mode, or ending recording stops the camera tracks.
- Recordings and uploads stay in browser memory. After **Reconstruct interface**, selected frames go to the local OCR process, or to OpenAI when a key is configured. The combined frame payload is limited to about 5 MB.
- **Projects → Project fit** calculates an explainable source-based estimate after choosing a screen and container. The weighted score includes framework support (25%), theme mapping (20%), action wiring (25%), basic accessibility (15%) and generated code size (15%). Each category expands to explain evidence and limitations. This is not a runtime benchmark or a guarantee that an interaction has been reconstructed.
- **Engines → Reframe Copy Polish** suggests conservative visible wording replacements and applies them only after review. Applying edits to a working feature rebuilds and checks it with the same actions and storage identity. The separate JS/TS comment reviewer uses the installed parser to preserve executable code, strings, license notices and tool directives. It is our own implementation, created at the user's request after the Turnitout engine source proved inaccessible; it is not the upstream engine.
- **Engines → Verify integrations** checks actual installed engine files and reviews the current canonical package. Real REA 6.7.0 analyzes its frontend, API server, storage runtime and schema together. Full feature creation, backup import and installation review rerun these checks, saving evidence IDs, file coverage, source hashes, policy hashes and limitations. Plain UI integration also runs REA for React and React Native. Native binary analysis is not included. Analysis parses inert source without executing it; at most four requests queue and temporary source files are removed afterward.
- **Built-in decision model** uses transparent local rules to recommend a supported destination, manual reconstruction, action wiring, or source review. It needs no API key and never claims to infer private backend code. Expand its evidence to separate frontend structure, local input state and missing business behavior.
- **Minimal generation** omits unused callbacks and input state, adds no dependencies, and retains original link destinations in the action contract for deliberate wiring. The bundled Ponytail policy guides vision prompts. Package checks parse JS/TS and JSON, count literal imports and flag dependencies beyond the React/Vite baseline. These are bounded structural checks; they do not prove all code is necessary or resolve dynamic dependency expressions. Ponytail itself is an instruction policy, not a compiler or optimizer.

See [UI research, scoring rules and design comparison](docs/UI-REFRESH.md).

## Optional vision

Copy `.env.example` to `.env`, set `OPENAI_API_KEY` locally, and restart the server. **Screenshot / Video / Camera → Reconstruct interface** then sends the selected frames and instructions to the configured OpenAI model. Website/HTML capture and REA source analysis do not use a model. Never put credentials in browser code or paste them into a component.

Without a key, macOS Vision OCR provides a tested local alternative for screenshots, cropped native screens and selected video/camera frames. Swift command-line tools compile the small OCR helper into ignored `.reframe/bin/`; images are processed in temporary owner-only files and removed afterward. The first frame supplies editable markup; additional ordered frame observations are retained in the response for review. Graphics, exact layout, animation and hidden behavior are not inferred by OCR. Live OpenAI inference remains untested without account configuration.

## Data and security

Clipboard items and theme live in this browser's localStorage. Export a backup before clearing site data or switching browsers. No cloud sync or account system is included. Storage failures are shown instead of claiming a successful save. Uploaded analysis source is transient. Connected project paths and undo snapshots are stored in the ignored `.reframe/` directory with owner-only file permissions. Snapshots include the affected source file; retain this directory while you need undo. Component captures and HTML edits stay in the browser. Explicit whole-website reconstructions are saved under `.reframe/websites/`, including page source, generated HTML/CSS and source URLs; keep this folder private and manage its backups.

Public URL capture validates all DNS addresses, pins the approved address for the connection, revalidates redirects, rejects private networks and credentials, and bounds download size/time. Imported markup is sanitized. Visual preview frames disable scripts and submissions; faithful browser captures may load their public source images/fonts. Working previews and installed website packages run only our authored runtime, with local form validation and receipts. Original scripts and private business logic are not copied. Review remote assets and unsupported actions before publishing.

## Reconstruct a public website

Open **Studio → Browser → Rebuild a whole website**. Supply a starting URL and up to seven same-origin pages, or enable bounded link discovery. A run captures one to eight pages with a 6 MB canonical website-data limit. Source stylesheets retain responsive rules, pseudo-elements and supported CSS animation; inline SVG and safe inline styles survive. Public fonts and explicitly downloadable/same-origin PDFs are bundled where available. Images remain online references. Lazy-page scanning also expands bounded “Show more photos” / “Load more” controls. Failed and uncaptured routes remain visible in the report; this is not an unlimited recursive site mirror.

**Export website ZIP** produces the captured pages, canonical metadata and a Node backend. Run `node server.mjs` in the extracted folder, then open http://localhost:5180/. Captured links navigate locally. Reframe supplies independent search, theme toggles, supported disclosures/carousels, image/card dialogs and event filtering. Unknown actions explain that they still need an explicit behavior contract. Original scripts, private APIs, AI assistants, payments and original account rules are never recovered.

Forms validate and save up to 200 local requests with durable receipts, idempotent retries and atomic writes; no email is sent. GET receipts do not return submitted field values. These are local workspace backends, not public multiuser services. **Save working website to clipboard** keeps a complete reusable package. **Save reusable components to clipboard** separately preserves captured download controls and forms with their source styling and own local backend. Other captured component and Originals workflows retain their existing branding options.
